# Feature list

Updated 2026-10-30. Super Colour is a professional colour tool and a sourced reference. Priorities follow practical work: inspect a supplied colour, understand the assumptions, compare options and take usable values into another application. Theory supports those tasks.

Every value must have a declared origin and status: user input, calculation, measurement or editorial approximation. Numerical proximity does not establish a historical identity. Systems and phases remain distinct from colours. No display-fidelity or physical production-match claims.

## Implemented locally; not yet deployed

- **JIS Z 8102 conventional colour names.** The 269 names of the standard's Appendix 1, each with the Munsell notation the standard assigns and the reference sRGB value the Japanese Wikipedia page JIS慣用色名 lists for it, generated by `scripts/import-jis-z8102.mjs` into `content/knowledge/japanese/jis-z8102.yaml`. Ten names that already had records (桜色, 藍色, 青, 白, 蘇芳, 勝色…) gained the JIS value as a second representation; the rest are new concepts. Readings come from the page's furigana, from 日本の色の一覧, or from the editor (24 names, flagged in the record). Everything is a discovery-route record: the names and notations are read from Wikipedia, not from the standard, whose text is restricted; the hex values are the page's own and are labelled as such. When a colour has several values, the one tied to a published notation is shown first (`primaryRepresentation`). The Laboratory, Theory and wheel selectors group these as "jis-z8102" beside the 13 traditional-vocabulary points, so the overlay stays readable; the Dictionary counts them as Japanese. Release 927 records, 286 colours.

- **Chinese traditional colour names.** The 24 valued entries of the Chinese Wikipedia page 中国传统色彩 not already in the database (绛, 朱, 红, 妃红, 品紅, 海棠, 胭脂, 绯, 茜, 殷紅, 桃红, 纁, 縓, 䞓, 褐色, 鴉青, 雪藍色, 精白, 雪白, 月白, 魚肚白, 象牙白, 縞, 灰色), hand-authored in `content/knowledge/chinese/traditional-colours.yaml`, plus the page's second 赭色 value on the existing 赭 record. Nine classical quotations relayed by the page (说文, 释名, 尚書·洪範, Zheng Xuan, Duan Yucai; the 縓 → 䞓 → 纁 dyeing sequence; 褐色 and 灰色 as intermediate colours) are discovered assertions in the page's wording, flagged as unchecked against an edition. Pinyin is the editor's. The page's unsourced 寓意 symbolism is not recorded. 青, 黄, 黑, 白 and 墨 still have no value. Release 1009 records, 310 colours.

- **CSS named colours.** All 148 keywords of CSS Color Module Level 4 § 6.1 (Candidate Recommendation Draft of 2026-10-29), generated by `scripts/import-css-named-colours.mjs` into `content/knowledge/web/css-named-colours.yaml` as 141 concepts (the seven grey spellings are second names on their gray concept). These are the first records whose values are published, not approximated: the keyword resolves to that sRGB value in every conforming implementation. The 16 VGA/HTML keywords are tagged. The old example file with rebeccapurple alone is retired; its records keep their ids. Chosen 2026-10-30 as the Western set because it is a modern standard in daily use; Werner, Ridgway and ISCC-NBS are not planned. Release 1436 records, 450 colours.

- **Collections in the screens (2026-10-30).** With 451 colours the screens group records by collection: a naming standard when a record belongs to one (JIS Z 8102, CSS named colours), otherwise its tradition (`pointGroup`, `groupLabel` in `apps/web/lib/records.ts`). The Dictionary's Tradition facet became Collection (URL parameter unchanged: `?tradition=jis-z8102`), cards and list rows name the collection, and the entry toolbar and Similar strip show it. The Laboratory has one "Documented" set (bottom bar, `data-testid="documented"`) that the nearest readout, source-led draws, the JSON export and the wheel overlay all use, so a designer working in JIS names sees JIS neighbours, not the nearest CSS keyword. Both wheels draw only documented points within L ±0.15 of the slice and say how many of the set are hidden; a dot on a slice means "at this lightness".

- **Colour space map (`/space`, 2026-10-30).** Every documented colour as a sphere at its OKLab position, the sRGB solid as a wireframe of its twelve cube edges mapped through OKLab, the palette as larger ringed spheres with numbered pins, and Chevreul's complementary pairs as dashed lines (relations are drawn only where a record documents one). Collection filter, the wheels' lightness band, hover readout with distance to the nearest palette colour, click to select with the five nearest records and links to entries, "Add to palette", "Look at it". State travels in the URL (`hex`, `set`, `band`, `l`, `focus`). Reached from the nav ("Map"), the Laboratory bottom bar (with its columns and documented set), each entry ("On the map", focused on the record) and the inspector. Three.js (0.170) is loaded only on this route in the browser; without WebGL the panel still lists every measured value. Approved from the mockup at https://claude.ai/artifact/9SdmdCJ8DoCxGcPsUsdEDT; spheres kept over cubes because a sphere reads as a position with no orientation. The user's stated reason is a more modern feel; the map's claims are limited to measured distance.

- **Light and dark themes (2026-10-30).** One token set with two value sets in `apps/web/lib/tokens.ts`, both contrast-checked by the unit test (every text/surface pair at 4.5:1 or better). White is the default whatever the OS prefers (user decision, 2026-10-30); a toolbar button switches to dark and back. The choice is kept in localStorage and applied by an inline script before the first paint, so there is no flash. Canvases and the 3D map read their greys and inks from the tokens and repaint when the theme changes. The colours of records, palettes and samples never change with the theme: only the chrome does. This reverses the 2026-10-14 decision to keep the background always white.

- **Intended pairs in Laboratory Contrast (2026-10-30).** The Contrast panel leads with the text-on-background pairs the designer declares (`pairs=0-1,2-0` in the address, kept through undo, column moves and removals, cleared when the palette is replaced). Each pair shows a 24 px and a 16 px sample, the ratio, and every WCAG 2.1 threshold by success criterion (1.4.3, 1.4.6, 1.4.11) with pass or fail; a Compare link opens the pair in the two-colour comparison. The all-pairs table follows. Measured on the sRGB values as displayed. `components/lab/contrast-panel.tsx`, `THRESHOLDS` in `lib/contrast.ts`.

- **Source-aware exports (2026-10-30).** Audit of the JSON export found record id, concept and label only: no citation, no approximation status, no recorded coordinates and no way to tell an edited column from a loaded one (an edit dropped the record). Now a column keeps its record through edits and shows "from <record> · edited"; `lib/exports.ts` writes CSS (a provenance comment above each variable), SVG (a `<g>` per swatch with `data-record`, `data-approximation`, `data-edited`, a `<desc>` and the JSON in `<metadata>`) and JSON (`record` with the representation's own space and coordinates, approximation status, method, source id and locator, `edited`; `sources` with full citations; `nearest` with collection and a note that it is a search, not an identification). `NamePoint` carries `provenance`; the lab page passes `sourceCitations()` and the site origin.

- **Two-colour comparison (`/compare?a=&b=&ra=&rb=`, 2026-10-30).** Both values (sRGB, OKLCh, OKLab, CIELAB D50), CIEDE2000 and OKLab ΔE each with its conditions, OKLCh differences by axis with hue as the smaller arc, the WCAG ratio with every threshold, and provenance per side when the address names the record (citation, approximation status, recorded coordinates, status badge; a warning if the compared value is not the record's). No perceptibility threshold is claimed. Reached from the inspector's nearby records and from intended pairs. `lib/compare.ts`.

- **Lightness view (2026-10-30).** A Laboratory panel showing each column as the grey of its OKLCh L (chroma and hue zero), markers on a 0–1 ruler, and the columns ordered by L with ΔL to the next. Labelled as a model estimate of perceived lightness, not a luminance (Y) measurement and not a substitute for a contrast ratio.

- **Neighbour view (2026-10-30).** Every column as a sample on every other column's ground, hex values beside each row and column header; the note says what shifts is simultaneous contrast on the display and the stored coordinates are unchanged.

- **Two-space gradients (2026-10-30).** A Laboratory panel interpolating a chosen pair in sRGB (gamma-encoded, as CSS `in srgb`) and in OKLCh with an explicit hue path (shorter, longer, increasing, decreasing), nine stops computed here, OKLCh stops outside sRGB gamut-mapped and marked. Copy CSS writes both as native `linear-gradient(… in oklch longer hue, …)` lines with stop-list fallbacks. The note says neither interpolation is right for every use. `lib/gradients.ts`.

- **Munsell reference (`/munsell?hex=` or `?notation=`, 2026-10-30).** A separately scoped lookup against RIT's `real.dat` transcription of the 1943 renotation (2734 chromatic samples, illuminant C, 2° observer), read only on the server. For a colour: the five nearest tabulated samples by CIE76 ΔE*ab in CIELAB under C after Bradford adaptation from D65, each with its published xyY, its sRGB approximation (mapped when outside), and the records whose source assigns that notation. For a notation: the tabulated value, or the nearest tabulated sample with the rule stated. Y is scaled by 0.975 per RIT's note. Linked from the inspector and from every entry with a Munsell tag (the JIS names). No interpolation and no perceptibility band. **Terms verified 2026-10-30:** RIT's website Terms of Use allow one downloaded copy "for your personal, noncommercial use only" and forbid copying, distributing or publishing site material; the resources page adds only "as is". So the file is not in the repository: `scripts/fetch-munsell.mjs` downloads a personal copy (or `MUNSELL_DATA_PATH` names one), the page explains when it is absent, and the data-dependent tests skip. A public deployment of the lookup needs RIT's permission, which is the user's call; `content/reference/munsell/README.md` records the terms and the request to make.

- **Documented relations near a palette (2026-10-30).** A Laboratory panel listing documented pairs, groups and layerings whose every member (represented by the value its entry shows, record id named) lies within a chosen OKLab distance (0.02–0.2, default 0.1) of some column, each matched to its nearest column with the distance. The method is printed in the panel, the match can be loaded as columns, and the note says a palette near a pair is not that pair. `documentedSets()` now includes layerings (kasane) with `kind` and `source`. `lib/relations.ts`.

- **Image colour extraction (`/extract`, 2026-10-30).** Decisions: processing is entirely in the browser (createImageBitmap → canvas → getImageData), nothing is uploaded or stored; the browser's decoder applies an embedded profile and the canvas is sRGB, an untagged image is treated as sRGB; the image is reduced to 256 px on its longest side, at most 20,000 opaque pixels are sampled on a grid, converted to OKLab and grouped by k-means (2–5 clusters) with a deterministic farthest-point start. Each observation is a cluster mean with its share of sampled pixels; nearest documented records are offered separately and labelled a search, not a name. Open in Laboratory or on the map. `lib/extract.ts`.

## Live since 2026-10-22

- **Chevreul system entry.** Six named landmarks within the documented 72-scale construction, three complementary pairs, and linked simultaneous-contrast passages. The Dictionary now has two systems (Chevreul and the Five Phases), the Laboratory loads the three pairs, and History links to the entry. The screen swatches have separate editorial provenance. Japanese layering remains a different kind of record, not a third system.
- **Colour inspector.** `/colour` accepts opaque 3- or 6-digit hex input. `/colour/fc2222` is an example canonical, shareable page. Short or uppercase route inputs redirect to lowercase six-digit URLs; invalid inputs return 404. Alpha, colour names and other input syntaxes are outside this first release.
  - Copy HEX, RGB, HSL, OKLCh, Lab and XYZ in CSS syntax. sRGB and OKLCh use D65; Lab uses D50 with Bradford adaptation; XYZ is D65 with reference-white Y = 1. Rounded readouts are identified as such. Achromatic polar readouts use an undefined hue.
  - Lightness and chroma variations show requested OKLCh steps and distinguish in-gamut from CSS-gamut-mapped screen values. Each step opens its rendered hex in the Laboratory. Chroma variations are not described as traditional “tones.”
  - Text samples against actual white and black, with numerical WCAG contrast and separate AA/AAA results for normal and large text. Intentionally failing samples remain demonstrations; surrounding controls and results are accessibility-audited.
  - Colour-vision simulations carry their model and limitations.
  - Nearby records show Euclidean OKLab distance, representation status, source citation and research-queue status where applicable. They are suggestions from a small collection, not colour identifications. Comparing display values opens both hex values in the Laboratory without asserting record identity.
  - Entry points: “Inspect colour” on each Laboratory column; “Inspect display colour” on a Dictionary record with a value; “Inspect this colour” on Dictionary hex searches; and “Inspect a hex” on the colour listing.
  - Dictionary entries share the inspector’s lightness-variation and contrast/simulation components. No duplicate conversion engine or new reference dataset was introduced.

These are code implementation statuses, not specialist approval or production deployment claims.

## Research required

- **Pantone integration.** No approved dataset or redistribution permission is recorded. A third-party hex table and trademark notice do not establish either. Determine an authorized integration, exact library/version and permitted usage before scheduling. Screen simulations must not be presented as physical-standard matches. See [Pantone’s terms](https://www.pantone.com/uk/en-gb/about/terms-of-use) and [simulation disclaimer](https://connect.pantone.com/?q=032+C).
- **Physical production conversions.** Generic CMYK percentages remain out of scope. A future CMYK workflow needs the relevant profile and output conditions. XYZ and Lab readouts from a declared sRGB input are already supported and do not require an arbitrary output-device profile.
- **Applied previews.** The inspector includes text/background samples. Broader compositions or product mockups are not in the current implementation; evaluate a concrete professional use case before expanding scope.

## Not planned

- Unsourced psychology or meaning prose, and undocumented colour-name databases presented as authority.
- Community feeds, wallpapers, lesson progress tracking or other portal features.
- Universal harmony ratings, perceptibility guarantees or automatic physical colour matching from screen values.
